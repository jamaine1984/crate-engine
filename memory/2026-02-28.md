# 2026-02-28 — NPC Animation Session

## What Happened
- Debugged NPC T-pose issue in Crate Engine
- Root cause: Mixamo animation track names use `mixamorigLeftArm` (no colon), not `mixamorig:LeftArm`
- KayKit knight bones are `UpperArmL` (suffix, no dot), not `UpperArm.L`
- Bone detection also needed suffix L/R matching (`n.endsWith('l')`)
- Fixed bone map + detection → animations loaded (idle/walk/run, 21 tracks each)
- NPC was on its back — needed `model.rotation.x = -Math.PI/2` to stand upright
- Facing direction code was overwriting rotation.x, fixed with `_mixamoRotFix` flag + `rotation.set(-PI/2, 0, -faceAngle, 'XYZ')`
- Arms still in T-pose because Mixamo quaternions assume different rest pose than KayKit skeleton
- Attempted rest-pose compensation (srcRest/tgtRest delta math) — made it worse (underground)
- Attempted replacing KayKit mesh with Soldier model — syntax error, user frustrated
- **Reverted to working v121 approach**: rotation fix + simple retarget (no rest-pose compensation)
- Deployed as v123: https://4dae85c1.crateship-games.pages.dev

## Key Lessons
- **Don't over-engineer when something works** — v121 had walking NPCs, should've stopped there
- **Mixamo track names**: `mixamorigBoneName.property` (no colon, no space)
- **KayKit knight bones**: `UpperArmL`, `LowerLegR` (suffix, no dot)
- **Rotation fix for cross-skeleton anims**: `-Math.PI/2` on X, preserve with rotation order `XYZ`
- **Rest-pose quaternion compensation is hard** — simple name remapping + rotation fix works better
- **Arms T-pose remaining issue**: quaternion values from Mixamo produce T-pose on KayKit because different bind poses. Needs proper rest-pose delta or use Soldier model directly as NPC visual.
